# IAM Setup Guide — Connecting an AWS Account

---

## Overview

AWS EOL Monitor needs read-only access to your AWS account to scan service versions. This is done using AWS IAM cross-account role assumption (STS AssumeRole). You create a read-only IAM role in your account and give the EOL Monitor backend permission to assume it.

No IAM user keys or long-lived credentials are ever required or stored.

---

## How It Works

```
Your AWS Account
  └─ IAM Role: EOLMonitorScanRole
       └─ Trust Policy allows:
            arn:aws:iam::495234635788:role/EOLMonitorBackendEC2Role
            with Condition: sts:ExternalId = <your-unique-id>

EOL Monitor Backend (AWS Account 495234635788)
  └─ EC2 Instance Role: EOLMonitorBackendEC2Role
       └─ Calls STS AssumeRole → EOLMonitorScanRole in your account
       └─ Gets temporary credentials (valid 1 hour)
       └─ Scans services with those credentials
       └─ Temporary credentials are never stored
```

---

## Step 1 — Generate ExternalId

When you start the "Add Account" flow in the dashboard, an ExternalId is automatically generated for your connection. It looks like:

```
eolm-ext-a3f9b2c1d7e04582
```

This ExternalId is stored with your account record and is required every time the backend assumes your role. It prevents confused-deputy attacks — even if someone else knows your role ARN, they cannot assume it without your specific ExternalId.

---

## Step 2 — Deploy the CloudFormation Stack

Copy the CloudFormation template from Step 2 of the Add Account flow and deploy it in your AWS account.

### Final CloudFormation Template

```yaml
AWSTemplateFormatVersion: "2010-09-09"
Description: "AWS EOL Monitor — Read-only scanner role"

Parameters:
  ExternalId:
    Type: String
    Description: Unique ExternalId generated by AWS EOL Monitor.

Resources:
  EOLMonitorRole:
    Type: AWS::IAM::Role
    Properties:
      RoleName: EOLMonitorScanRole
      AssumeRolePolicyDocument:
        Version: "2012-10-17"
        Statement:
          - Effect: Allow
            Sid: AllowEOLMonitorBackendAssumeRole
            Principal:
              AWS: "arn:aws:iam::495234635788:role/EOLMonitorBackendEC2Role"
            Action: sts:AssumeRole
            Condition:
              StringEquals:
                sts:ExternalId: !Ref ExternalId
      ManagedPolicyArns:
        - !Ref EOLMonitorPolicy

  EOLMonitorPolicy:
    Type: AWS::IAM::ManagedPolicy
    Properties:
      PolicyDocument:
        Version: "2012-10-17"
        Statement:
          - Effect: Allow
            Action:
              # Lambda
              - lambda:ListFunctions
              # EKS
              - eks:ListClusters
              - eks:DescribeCluster
              # RDS
              - rds:DescribeDBInstances
              - rds:DescribeDBClusters
              - rds:DescribeDBEngineVersions
              # ElastiCache
              - elasticache:DescribeCacheClusters
              # EC2
              - ec2:DescribeInstances
              - ec2:DescribeImages
              - ec2:DescribeRegions
              # SSM (for EC2 OS detection)
              - ssm:DescribeInstanceInformation
              - ssm:GetInventory
              # CodeBuild
              - codebuild:ListProjects
              - codebuild:BatchGetProjects
              # Amazon MQ
              - mq:ListBrokers
              - mq:DescribeBroker
              # AWS DMS
              - dms:DescribeReplicationInstances
              # Amazon MWAA
              - mwaa:ListEnvironments
              - mwaa:GetEnvironment
              # ECS (Fargate platform version scanning)
              - ecs:ListClusters
              - ecs:ListServices
              - ecs:DescribeServices
              # SageMaker (Notebook instance lifecycle)
              - sagemaker:ListNotebookInstances
              - sagemaker:DescribeNotebookInstance
              # Elastic Beanstalk (platform branch lifecycle)
              - elasticbeanstalk:DescribeEnvironments
              - elasticbeanstalk:DescribePlatformVersion
              # AWS Batch (compute environment AMI lifecycle)
              - batch:DescribeComputeEnvironments
              # EMR
              - elasticmapreduce:ListClusters
              - elasticmapreduce:DescribeCluster
              # MSK
              - kafka:ListClustersV2
              - kafka:DescribeCluster
              # OpenSearch (both new and legacy API)
              - opensearch:ListDomainNames
              - opensearch:DescribeDomain
              - opensearch:DescribeDomains
              - es:ListDomainNames
              - es:DescribeDomain
              - es:DescribeDomains
              - es:DescribeElasticsearchDomain
              - es:DescribeElasticsearchDomains
              # Glue
              - glue:ListJobs
              - glue:GetJob
              - glue:GetJobs
              # CloudFront
              - cloudfront:ListFunctions
              # ECR
              - ecr:DescribeRepositories
              - ecr:DescribeImages
              # DocumentDB
              - rds:DescribeDBClusters
              # Neptune
              - neptune:DescribeDBClusters
            Resource: "*"

Outputs:
  RoleArn:
    Description: Role ARN to paste into AWS EOL Monitor.
    Value: !GetAtt EOLMonitorRole.Arn
  ExternalId:
    Description: ExternalId used for this connection.
    Value: !Ref ExternalId
```

### Deploy via CLI

```bash
aws cloudformation deploy \
  --template-file eol-monitor-role.yaml \
  --stack-name EOLMonitorScanRole \
  --parameter-overrides ExternalId=<your-external-id> \
  --capabilities CAPABILITY_NAMED_IAM \
  --region <your-region>
```

---

## Step 3 — Copy the Role ARN

After CloudFormation completes, go to **Outputs** tab and copy the `RoleArn` value. It looks like:

```
arn:aws:iam::123456789012:role/EOLMonitorScanRole
```

Paste this into Step 3 of the Add Account flow in the dashboard.

---

## Step 4 — Validate Role

The dashboard validates the role before saving. Validation:
1. Calls `STS AssumeRole` using the provided Role ARN + ExternalId.
2. Calls `STS GetCallerIdentity` to confirm the assumed identity.
3. Confirms the assumed account ID matches the AWS Account ID you provided.

If validation passes, the account is saved and ready to scan.

---

## Why MonitorAccountId Is No Longer Required

Earlier versions required customers to supply the monitor account ID (495234635788) as a CloudFormation parameter. This was removed because:

- The backend EC2 role ARN is fixed and known.
- Hardcoding it in the template is simpler and safer.
- Customers cannot accidentally supply the wrong account ID.

The Principal in the trust policy is now hardcoded:

```yaml
Principal:
  AWS: "arn:aws:iam::495234635788:role/EOLMonitorBackendEC2Role"
```

---

## Read-Only Policy

The policy grants only read access. Specifically:

- `Describe*`, `List*`, `Get*`, `Batch*` actions only.
- No `Create*`, `Delete*`, `Update*`, `Modify*`, `Put*`, `Run*`.
- No `InvokeFunction`, `TerminateInstances`, `DeleteDB*`, or any destructive action.

Customers can add a `Deny` statement to further restrict regions or services if needed.

---

## STS Validation Flow

```
Dashboard UI
  └─ POST /workspaces/:wsId/accounts/validate-role
       └─ { roleArn, externalId, awsAccountId }
            └─ Backend calls STS AssumeRole
                 ├─ Success → calls GetCallerIdentity
                 │    └─ Confirms account ID matches awsAccountId
                 │         ├─ Match → {valid: true}
                 │         └─ Mismatch → {valid: false, error: ACCOUNT_MISMATCH}
                 └─ Failure → {valid: false, error: ASSUME_ROLE_FAILED}
```

## Troubleshooting AssumeRole Errors

### ASSUME_ROLE_FAILED

| Cause | Fix |
|---|---|
| Wrong Role ARN format | Must be `arn:aws:iam::123456789012:role/RoleName` |
| Role not yet created | Wait 10–30s for CloudFormation to complete |
| Wrong Principal in trust policy | Must be `arn:aws:iam::495234635788:role/EOLMonitorBackendEC2Role` |
| Missing ExternalId condition | Re-deploy CloudFormation with correct ExternalId parameter |
| ExternalId mismatch | ExternalId in dashboard must match ExternalId used in CloudFormation |

### ACCESS_DENIED during scan

| Cause | Fix |
|---|---|
| Missing OpenSearch permissions | Add `opensearch:DescribeDomains`, `es:DescribeDomains`, `es:DescribeElasticsearchDomains` |
| Missing SSM permissions | Add `ssm:DescribeInstanceInformation`, `ssm:GetInventory` |
| Missing Amazon MQ permissions | Add `mq:ListBrokers`, `mq:DescribeBroker` |
| Missing AWS DMS permissions | Add `dms:DescribeReplicationInstances` |
| Missing MWAA permissions | Add `mwaa:ListEnvironments`, `mwaa:GetEnvironment` |
| Missing ECS permissions | Add `ecs:ListClusters`, `ecs:ListServices`, `ecs:DescribeServices` |
| Missing SageMaker permissions | Add `sagemaker:ListNotebookInstances`, `sagemaker:DescribeNotebookInstance` |
| Missing Beanstalk permissions | Add `elasticbeanstalk:DescribeEnvironments`, `elasticbeanstalk:DescribePlatformVersion` |
| Missing AWS Batch permissions | Add `batch:DescribeComputeEnvironments` |
| Service not enabled in region | Expected — scanner logs a warning and continues |
| SCP blocking the role | Check AWS Organizations Service Control Policies |

### ACCOUNT_MISMATCH

The AWS Account ID you typed in Step 1 does not match the account that the role ARN belongs to. Verify the role ARN and the account ID.

## Common Mistakes

| Mistake | Symptom | Fix |
|---|---|---|
| Principal ARN has wrong account | ASSUME_ROLE_FAILED | Re-deploy CF with correct ExternalId; verify account 495234635788 |
| ExternalId not passed in CLI deploy | ASSUME_ROLE_FAILED | Add `--parameter-overrides ExternalId=<id>` |
| Missing OpenSearch `es:*` permissions | Scan succeeds but OpenSearch resources missing | Add `es:ListDomainNames`, `es:DescribeDomains`, `es:DescribeElasticsearchDomains` |
| Wrong Role ARN pasted (development role) | ACCOUNT_MISMATCH | Copy RoleArn from CF Outputs, not from IAM console search |
| Role created in wrong region | Role assumed but scan finds no resources | CF/IAM roles are global; verify region selection in scan settings |
| Copied ExternalId from browser URL | ASSUME_ROLE_FAILED | Copy ExternalId from Step 1 in the dashboard, not the URL |
